# История изменений

## 1.0.1

### Исправлено

- В команде запуска Gunicorn 26.2 отключён управляющий сокет (`--no-control-socket`). Контейнер больше не пытается создавать его в отсутствующем домашнем каталоге пользователя приложения, что приводило к ошибке доступа в стартовых логах.
- В CI добавлена проверка реального старта production-конфигурации с непривилегированным пользователем и файловой системой только для чтения, включая проверку отсутствия стартовых `ERROR` и `Permission denied`.
- В примере Nginx добавлено явное проксирование `/static/` в приложение, чтобы файлы из образа не искались на хосте и не перехватывались regex-location. В инструкции добавлена диагностика ответов контейнера и публичного прокси.
- HTTP smoke-проверка дополнена загрузкой SVG с иконками, кроме страницы входа и CSS.

Схема БД и складские данные не меняются. Обновление выполняется с прежними именем Compose-проекта, конфигурацией окружения и томом PostgreSQL. Допустимые домены остаются настройкой окружения.

## 1.0.0

Первая подготовленная версия склада запчастей с запуском Django и PostgreSQL через Docker Compose.

### Складской учёт

- Справочники запчастей, фирм, складов, контрагентов, работников и транспорта.
- Приходные накладные, списания и перемещения между складами; проведение и отмена документов с проверкой остатков.
- Заявки операторов с подтверждением или отклонением проверяющим, история решений и защита от самосогласования после смены роли.
- Инвентаризация и многострочные ведомости, ручные корректировки с причиной и автором, карточка движения и журнал изменений.
- Минимальные остатки и список закупок с учётом всех ценовых партий одной позиции.
- Аналитика, отчёты об обороте и XLSX-выгрузки; импорт накладных из XLSX с предварительной проверкой.
- Роли оператора, проверяющего и администратора, управление складскими учётными записями и смена пароля.

### Запуск и сопровождение

- PostgreSQL 17 в отдельном контейнере с постоянным томом и проверкой готовности; поддержка SQLite для отдельного локального запуска сохранена.
- Последовательное выполнение складских записей в PostgreSQL под транзакционной блокировкой для защиты остатков при нескольких процессах приложения.
- Общий образ Django/Gunicorn, одноразовое применение миграций и настройка ролей до запуска веб-приложения.
- Базовый Compose, режим разработки с перезагрузкой кода и подключением БД из IDE, отдельные production-настройки за HTTPS-прокси.
- Настройки через переменные окружения и отдельные примеры `.env` для локального и боевого запуска; секреты и резервные копии исключены из Git и образа.
- HTTP-проверка готовности `/healthz/`, сборка статических файлов и инструкции обновления, резервного копирования и контрольного восстановления PostgreSQL.
- Версия приложения `1.0.0`, маркировка контейнерного образа и автоматические проверки в CI.

### Переход с прежней версии

- Compose использует PostgreSQL вместо SQLite. Прежний файл SQLite и том `warehouse-data` автоматически не переносятся и не удаляются. Перенос данных требует отдельной проверки документов, остатков, пользователей и прав.
- Для PostgreSQL используйте `pg_dump` и `pg_restore`; `warehouse_database backup/restore` предназначены для файловой SQLite. Проверка старых SQLite-копий через `warehouse_database verify` сохранена.
- Перед обновлением сохраните прежний образ и резервную копию, проверьте восстановление в отдельный Compose-проект. Откат только образа не отменяет миграции БД.

Порядок проверки и публикации версии описан в [RELEASE.md](RELEASE.md), команды развёртывания — в [deploy/README.md](deploy/README.md).
