# Миграции складского учёта

Цепочка миграций описывает схему с первой версии склада. Django применяет файлы по зависимостям и хранит список применённых миграций в базе. Изменения схемы оформляйте новой миграцией после последней применённой в проекте.

- Миграции `0001`–`0031` сохраняют историю прежних таблиц и справочников.
- `0032` возвращает исторические модели под управление Django и переименовывает существующие столбцы. Она учитывает базы, где часть имён уже исправляли вручную.
- `0033` вводит защиту ссылок складских документов и пересчитывает признаки инвентаризационных расхождений.
- Последующие миграции добавляют точный учёт количества, корректировки, отмену операций, пересчёты, артикулы, минимумы, перемещения, накладные и ведомости.

В миграциях данных берите исторические модели через `apps.get_model()` и используйте соединение, переданное через `schema_editor`. При проверке обновления используйте отдельную копию существующей базы. План применения и соответствие схемы моделям можно проверить из корня проекта.

```sh
python manage.py showmigrations spares
python manage.py migrate --plan
python manage.py makemigrations --check --dry-run
```

Порядок резервного копирования и восстановления описан в [основном README](../../README.md#обновление-существующего-склада).
