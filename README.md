# Склад запчастей

На главной странице видны позиции в наличии и последние операции. В разделе «Остатки» можно найти запчасть по названию или артикулу, отфильтровать позиции и скачать выборку в XLSX. Из строки остатка доступны списание, перемещение, пересчёт и история. В «Минимальных остатках» правила применяются к сумме всех ценовых партий одной запчасти, фирмы, склада и единицы измерения. Фильтр «Только к пополнению» показывает и правила для позиций с нулевым остатком.

- **Приход.** Оформите накладную с одной или несколькими позициями. Для импорта скачайте шаблон из раздела «Накладные», заполните до 100 строк и загрузите файл. После предпросмотра оператор отправляет накладную на проверку, а проверяющий может провести её сразу.
- **Расход и перемещение.** В расходе форма показывает доступное количество. Для перемещения укажите исходную строку остатка, склад назначения и количество. Движение меняет оба остатка и сохраняется отдельным документом.
- **Отмена.** Приход, расход, накладную или перемещение можно отменить с причиной. В журнале сохраняются исходные реквизиты и отметка об отмене. Если для обратной операции недостаточно количества, приложение покажет ошибку. Для проведения укажите сегодняшнюю или прошедшую дату.
- **Инвентаризация.** Пересчёт сохраняет фактическое количество и учётный остаток на этот момент. Следующие операции меняют текущий остаток, а результат пересчёта остаётся в истории. Изменение учётного количества оформите отдельной ручной корректировкой.
- **Карточка движения.** Откройте «Движение» из строки остатка. История этой позиции объединяет документы, отмены, перемещения и ручные корректировки с переходами к источникам.
- **Инвентаризационная ведомость.** Оператор отправляет пересчёт нескольких позиций одного склада на проверку. Ведомость проверяющего проводится при создании. Подтверждённые строки связаны с корректировками остатков.
- **Список закупок.** Раздел «Закупки» показывает разницу между минимумом и доступным количеством. XLSX содержит отфильтрованные позиции на отдельных листах по складам.
- **Аналитика.** Раздел показывает суммы прихода и расхода по месяцам, наибольшие списания и текущее состояние запасов. Для операций выберите период, фирму и склад. Снимок остатков относится к текущему моменту. Отчёт об обороте разбивает количества по запчастям и единицам измерения и выгружает выборку в XLSX.

## Локальный запуск

Нужен Python 3.13. Команды для PowerShell, из корня репозитория:

```powershell
python -m venv .venv
$env:DEBUG = '1'
.venv/Scripts/python.exe -m pip install -r requirements.txt
.venv/Scripts/python.exe manage.py migrate
.venv/Scripts/python.exe manage.py configure_warehouse_roles
.venv/Scripts/python.exe manage.py createsuperuser
.venv/Scripts/python.exe manage.py runserver
```

Откройте [http://127.0.0.1:8000](http://127.0.0.1:8000) и войдите. В Linux и macOS используйте `.venv/bin/python` и `export DEBUG=1`.

В «Справочниках» заведите фирму, склад, запчасть и контрагента. Для списаний добавьте работника и запись в справочнике «Водители-транспорт-прицепы». Складская работа доступна с главной страницы. Войдите под первым администратором и создайте отдельную учётную запись для каждого сотрудника через «Управление».

При изменении учётного остатка укажите причину. «Журнал корректировок» показывает дату и время, автора, причину и количество до и после. Записи создаются также при вводе ненулевого начального остатка. Просмотр журнала доступен с правом `spares.view_stockadjustment`. Для отмены документов используется право Django `delete` соответствующей модели. Для пересчётов, минимумов и перемещений назначьте отдельные права моделей `InventoryCount`, `StockMinimum` и `StockTransfer`.

## Роли склада

Веб-интерфейс показывает разделы и действия по роли сотрудника.

| Роль | Полномочия |
| --- | --- |
| Оператор | Подаёт заявки на приход, списание и перемещение. Отслеживает статус и причины отклонения в «Моих заявках». Записывает пересчёты и подаёт ведомости. |
| Проверяющий | Проводит и отклоняет заявки и ведомости из очереди «На проверку». Его собственные новые операции проводятся сразу. Может отменять документы, корректировать остатки и вести справочники и минимумы. |
| Администратор | Выполняет работу проверяющего и управляет складскими учётными записями, включая назначение роли, смену пароля и отключение доступа. |

При проверке заявок сервер повторно проверяет реквизиты и доступный остаток. В журнале заявок хранятся автор, время и решение. Отклонение требует причины. Приложение защищает старые заявки от самосогласования после смены роли автора.

После миграций запустите `configure_warehouse_roles`, чтобы создать или обновить три группы. Для существующих учётных записей можно сразу назначить роли командой:

```sh
docker compose run --rm web python manage.py configure_warehouse_roles --operator operator --reviewer reviewer --admin warehouse_admin
```

Назначение заменяет прежнюю складскую роль. Для существующих сотрудников проверьте индивидуальные права и другие группы в `/admin/`, поскольку Django складывает все выданные разрешения. «Управление» обслуживает обычные аккаунты с одной складской ролью. Системные и специально настроенные аккаунты обслуживаются через `/admin/`.

## Локальные проверки

```powershell
$env:DEBUG = '1'
.venv/Scripts/python.exe -m pip check
.venv/Scripts/python.exe manage.py check
.venv/Scripts/python.exe manage.py makemigrations --check --dry-run
.venv/Scripts/python.exe manage.py test
```

У каждого модуля, класса, функции и метода в собственном Python-коде должен быть русскоязычный docstring. Описание должно объяснять назначение и важные условия работы. Тест `spares.tests.test_docstrings` проверяет это правило при локальном прогоне.

Устройство складского учёта, транзакций и интерфейса описано в [README приложения склада](spares/README.md). Правила сохранения истории схемы собраны в [README миграций](spares/migrations/README.md).

## Развёртывание через Docker Compose

1. Скопируйте `.env.example` в `.env` и заполните `SECRET_KEY` уникальным значением. Сгенерировать его можно командой `python -c "import secrets; print(secrets.token_urlsafe(64))"`.
2. Соберите образ и примените миграции. Для новой базы создайте первого пользователя.

   ```sh
   docker compose build
   docker compose run --rm web python manage.py migrate --noinput
   docker compose run --rm web python manage.py configure_warehouse_roles
   docker compose run --rm web python manage.py createsuperuser
   docker compose up -d
   ```

3. Откройте `http://127.0.0.1:8000` на сервере. Контейнер слушает на loopback хоста, порт можно сменить через `WAREHOUSE_PORT`.

Для доступа по сети настройте обратный прокси с TLS перед приложением. Укажите домен в `ALLOWED_HOSTS`, HTTPS-адрес с протоколом в `CSRF_TRUSTED_ORIGINS` и установите `WAREHOUSE_HTTPS=1`. Прокси должен передавать исходный `Host` и сам устанавливать `X-Forwarded-Proto`. Проверка с такой конфигурацией:

```sh
docker compose run --rm web python manage.py check --deploy --fail-level ERROR
```

Проверка может вывести рекомендации Django по HSTS для всех поддоменов и списку preload. Эти параметры зависят от настройки домена.

Статику собирает Docker при сборке. Gunicorn работает с одним процессом, SQLite хранится в именованном томе `warehouse-data`. Используйте один экземпляр приложения на этот том.

### Обновление существующего склада

Остановите старый экземпляр и сделайте резервную копию SQLite. Прогоните миграции на копии и проверьте остатки до обновления рабочей базы. Если рабочая база уже в томе Compose, при остановленном сервисе копию можно получить командой `docker compose cp web:/data/db.sqlite3 ./warehouse-backup.sqlite3`.

При переходе со старой версии проверьте записи прихода и расхода с будущими датами. Ранее проведённые операции сохраняют исторически начисленный остаток, и в журнале они помечены. Пересчёты, внесённые до появления датированных записей, остаются в карточках остатков с пометкой об отсутствии даты.

Команда `python manage.py reconcile_stock` после миграции покажет возможные дубли остатков. После сверки с фактическими данными запустите `python manage.py reconcile_stock --merge ID_СОХРАНЯЕМОЙ_СТРОКИ ID_ДУБЛЯ …`, перечислив все строки одной группы. Команда суммирует приход, расход и фактический остаток. При конфликте планов или данных инвентаризации она потребует сначала сверить их. В Docker добавьте префикс `docker compose run --rm web` к командам управления.

Для установки существующей базы в новый том перед первым запуском приложения выполните на Linux из каталога проекта:

```sh
docker compose run --rm --user root \
  --volume "$(pwd)/warehouse-backup.sqlite3:/backup.sqlite3:ro" web \
  sh -c 'test ! -e /data/db.sqlite3 && install -o warehouse -g warehouse -m 600 /backup.sqlite3 /data/db.sqlite3'
```

Затем выполните `docker compose run --rm web python manage.py migrate --noinput`, `docker compose run --rm web python manage.py configure_warehouse_roles` и `docker compose up -d`. При обновлении контейнера используйте прежний том. Команда `docker compose down -v` удаляет данные.

### Контрольное восстановление

Для проверки копии разверните её в отдельном контейнере с пустым томом. Для копии той же версии приложения выполните `python manage.py migrate --check`. В SQLite проверьте `PRAGMA integrity_check` и `PRAGMA foreign_key_check`. Ожидаемые результаты — `ok` и пустой список. Затем войдите под оператором и контролёром, сравните контрольные остатки и документы, проверьте доступные действия обеих ролей.
